# source-grounding

세 규칙을 지킨다. 하나라도 빠지면 결과물을 사용자에게 보여 주지 않는다.

## 1. 원문을 파일로 남기고, 원문을 근거로 쓴다

- 작업을 시작할 때 근거가 되는 원문을 **가공하지 않고** 남는 자리에 저장한다.
  긴 작업이면 `_state/<task>-sources/`(scratchpad 밖), 짧은 작업이면 scratchpad.
- 파일명은 `<출처종류>-<식별자>-fetched-<YYYYMMDD>.<ext>` — 이름만 보고 무엇의 원본인지 알게 한다.

| 출처 | 파일명 예 | 내용 |
|---|---|---|
| Slack 스레드 | `slack-thread-C0BDSEAB4Q2-1791939603-fetched-20261015.json` | API 응답 그대로 |
| Jira | `jira-PRIVACY-1959-fetched-20261015.json` (+ 필드만 뺀 `.md`) | 응답 그대로 |
| 메일 | `mail-<보낸사람>-<YYYYMMDD>-fetched-<날짜>.md` | 본문 원문 |
| 문서·계약 | `doc-<문서명>-<버전·날짜>.<원래 확장자>` · `contract-<이름>-<날짜>.txt` | 원본 파일, 텍스트 추출본 |

- 우리가 만든 메모·요약은 이 폴더에 넣지 않는다. 원본을 구할 수 없으면(DRM 등) 없다고 적고 넘어가지 않는다.
- 요약은 원문을 **대신하지 않는다.** 요약을 만들더라도 줄마다 출처 꼬리표(규칙 2)를 붙이고,
  다른 사람·worker에게는 요약이 아니라 **원문 파일 경로**를 준다.
- 사용자가 말한 결정과, 상대와 이미 합의된 것은 `_state/<task>-decisions.md`에 한 줄씩 모은다.
  `날짜 | 결정·합의 내용 | 출처`. 확인 요청을 만들기 전에 이 목록을 먼저 본다.

## 2. 모든 문장에 출처 꼬리표를 붙인다

요건·합의·수치·결정을 쓰는 문장 끝 괄호에 출처를 붙인다.
**꼬리표는 "누가 내용을 만들었나"가 아니라 "누가 정하기로 했나"로 고른다.**

| 꼬리표 | 언제 | 예 |
|---|---|---|
| 요청 | 상대가 원문에서 요구·합의한 것 | `(요청 · Slack 정민님 10-14 17:36)` · `(요청 · Jira PRIVACY-1959 P-BP_LG_003)` |
| 제안 · 상대 확인 필요 | 상대가 정하기로 한 영역(예: 개인정보 문구·보유기간·범위)에 우리가 만든 안 | `(제안 · 정민님 확인 필요 — 근거 Slack 10-14 17:36 2-c)` |
| 구현 사항 | 문구와 무관한 코드 동작으로 우리가 정한 것 | `(구현 · scripts/audit-log-core.mjs:16)` |
| 사용자 결정 | 사용자가 대화에서 정한 것 | `(윤희님 결정 10-15)` |

- 상대가 "정하겠다/함께 조정하겠다"고 한 영역은 우리가 쓴 안이 있어도 **결정이 아니라 제안**이다. "확정"으로 표시하지 않는다.
- **"구현 사항"은 상대에게 확인을 요청하지 않는다.** 알릴 필요가 있으면 알리기만 한다.
- 한 항목에 요청과 제안이 섞이면 줄을 나눠 "요청: … / 제안: …"으로 따로 쓴다.
- 출처가 둘 이상이고 내용이 다르면 둘 다 적고 차이를 드러낸다.
  예: "Slack은 1년(Slack 정민님 10-14 14:59), Jira는 2년 이상(Jira PRIVACY-1959 P-BP_LG_003)".
- 원문에 없는 용어를 새로 만들지 않는다. 쓸 때는 "우리 표현"이라고 밝힌다.
- 화면·캔버스·문서처럼 사람이 볼 결과물에도 항목마다 출처 종류가 보이게 한다(꼬리표·색).

## 3. 보내기 전에 원문 대조 검증을 따로 돌린다

회신 초안, 확인 요청, 검토 메모, 요건 목록을 사용자에게 내놓기 **전에** 검증을 한 번 돌린다.

- 검증자는 만든 사람과 분리한다. native subagent(읽기 전용)에게 **원문 파일, decisions.md,
  초안만** 준다. 작업 과정이나 요약은 주지 않는다.
- 검증자가 초안을 한 줄씩 보고 아래 다섯 가지를 표로 돌려준다.

| 표시 | 뜻 |
|---|---|
| 출처 없음 | 꼬리표가 없거나, 꼬리표가 가리키는 원문에 그 내용이 없다 |
| 원문 불일치 | 수치·기간·대상이 원문과 다르다 |
| 이미 합의됨 | decisions.md나 원문에서 이미 답을 받은 것을 다시 묻는다 |
| 꼬리표 오류 | 제안을 확정/결정으로 쓰거나, 구현 사항을 상대 요건처럼 쓰거나 확인을 요청한다 |
| 원문 누락 | 원문에 있는 요건(특히 미완료·Blocked)이 초안 어디에도 없다 |

- 지적이 나오면 고친 뒤 사용자에게 보여 준다. 고치지 않은 지적은 그대로 함께 보고한다.

### 대조 방법 세 가지

| 방법 | 하는 일 | 잡는 것 |
|---|---|---|
| 인용 일치 검사(기계) | 초안의 `“…”` 인용이 원문 파일에 글자 그대로 있는지 확인한다. `python3 -I <이 스킬>/scripts/quote_check.py <초안> <원문 폴더>` | 원문에 없는 인용, 바뀐 수치 |
| 추적표 | 원문 요청을 한 줄씩 행으로, 처리한 곳(메모 id·회신 문단)을 열로. 빈칸 = 누락 | 원문 누락(특히 Blocked·미완료) |
| 문구 diff | 상대가 준 문구와 우리 문구를 단어 단위로 비교한다. `git diff --no-index --word-diff <원본.md> <우리.md>` | 상대 문구를 임의로 바꾼 곳 |

- 인용은 원문에서 **복사해 붙인다.** 고쳐 쓰면 인용이 아니다(따옴표 없이 요약으로 쓰고 꼬리표만 단다).
- 인용 일치 검사가 실패하면 검증 agent 전에 먼저 고친다.

### 검증자 프롬프트 틀

```
아래 초안을 원문과 대조해 검증해라. 고치지 말고 표만 돌려줘라.
원문: <파일 경로들>
결정·합의 목록: <_state/<task>-decisions.md>
초안: <파일 경로>
표 열: 초안 위치(줄/메모 id) · 표시(출처 없음|원문 불일치|이미 합의됨|꼬리표 오류|원문 누락) · 근거 원문 인용(15단어 이내) · 고칠 방향
원문 누락은 원문 쪽 항목 기준으로 따로 모아라.
```

## worker에게 넘길 때

작업 계약(`herdr-orchestration`의 Task contract)에 `Sources:` 줄을 넣는다.
`Sources: <원문 파일 경로들> · decisions: <경로> · 규칙: source-grounding 스킬 1~3`
