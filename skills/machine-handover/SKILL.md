# machine-handover

SSH로 원격 머신에 붙어 일하다 보면 "이건 저쪽(내가 앉아 있는 로컬 맥 등)에서 해야 하는데"가
자주 생긴다 — 소리 재생, GUI 설정, 로컬 키체인, 로컬에만 있는 파일. 이때 기본값은
**프롬프트를 써서 넘기는 게 아니라, 여기서 직접 할 수 있는지부터 보는 것**이다.
넘기는 건 사람이 복사·붙여넣기·결과 전달을 해야 해서 비싸다.

순서: **대상 특정 → 직접 실행 시험 → (안 되면) 핸드오버 프롬프트 → 시크릿 검사 → 결과 회수 방법 명시.**

## 1. 대상 머신 특정

```bash
herdr machine list                 # herdr에 저장된 머신 (label · host)
grep -iA5 '^Host ' ~/.ssh/config   # 별칭 · HostName · User · IdentityFile
echo "$SSH_CLIENT"                 # 지금 나에게 붙어 온 쪽의 IP — "로컬 맥"은 대개 이것
```

"로컬 맥"이라고만 하면 **`$SSH_CLIENT`의 IP와 `~/.ssh/config`의 `HostName`을 대조**해 어느
별칭인지 정한다. herdr의 label(예: `home`)과 ssh 별칭은 이름이 다를 수 있다.

## 2. 직접 실행 시험 — 되면 넘기지 않는다

```bash
ssh -o BatchMode=yes -o ConnectTimeout=5 <별칭> 'whoami; hostname; which <필요한 명령>'
```

- 성공하면 **핸드오버 없이 여기서 `ssh <별칭> ...`으로 끝낸다.** 사람에게는 "넘길 필요 없었다"고 한 줄로 알린다
- 실패 원인별:
  - `Permission denied (publickey)` → 키 미등록. 저쪽에서 `authorized_keys` 추가가 필요 → 3번으로
  - `Connection refused` / timeout → 저쪽 원격 로그인 꺼짐 또는 네트워크 경로 없음 → 3번으로
  - 명령이 GUI·권한 팝업(TCC, 키체인 승인)을 요구 → SSH로는 불가 → 3번으로

## 3. 핸드오버 프롬프트 작성

받는 에이전트는 **이 대화를 모른다.** 아래 칸을 모두 채운다.

```
## 목적
<무엇을 왜 — 한두 문장>

## 현재 상태
<이미 된 것 · 이쪽 머신 이름/주소 · 관련 경로>

## 할 일
1. <명령 그대로 — 복사해서 실행 가능하게>
2. ...

## 검증
<성공이면 무엇이 보여야 하는지 — 명령과 기대 출력>

## 하지 말 것
<건드리면 안 되는 것 · 범위 밖 · 되묻고 진행할 것>

## 끝나면
<결과로 무엇을 사람에게 알려 달라 — 예: 출력 마지막 3줄, 생성된 값>
```

- 명령은 **추상 서술이 아니라 실행 가능한 그대로** 쓴다 ("키를 등록하세요" ✗ → `echo '<pubkey>' >> ~/.ssh/authorized_keys` ✓)
- 공개키처럼 저쪽에 필요한 값은 프롬프트에 **직접 박아 준다** — 받는 쪽은 이쪽 파일을 읽을 수 없다
- 끝나고 이쪽에서 이어서 할 일(예: 2번 재시험)이 있으면 "끝나면" 칸에 적고, 사람에게도 "다 되면 알려 달라"고 말한다

## 4. 시크릿 검사

프롬프트를 내놓기 전에 훑는다: 토큰·API 키·비밀번호·개인키(**공개키만 허용**)·세션 쿠키.
필요하면 "값은 `.env`의 `X`를 쓴다"처럼 **이름만** 넘긴다. 프롬프트는 채팅·클립보드에 남는다.

## 알아둘 것

- **SSH로 붙어 있으면 소리·알림·GUI는 서버 쪽에서 난다.** 사람에게 들리게 하려면
  서버 → 사람 머신으로의 역방향 SSH(`ssh <별칭> say ...`)가 필요한데, 이게 이미 되는 경우가 많다.
  이 스킬을 만든 계기가 "로컬 에이전트에게 등록 프롬프트를 줘야 하나?"였는데, 확인해 보니
  역방향 키가 이미 있어서 넘길 필요가 없었다
- `ssh` 시험에는 **`BatchMode=yes`를 꼭 붙인다.** 없으면 비밀번호 프롬프트에서 멈춰 에이전트가 계속 기다린다
- 대상이 VPN·tailnet 주소면 그 머신이 잠들었을 때 연결이 안 된다 — 실패를 "키 문제"로 단정하지 말고 timeout인지 먼저 본다
- 전제: macOS/Linux, `ssh`. herdr가 없으면 1번의 `herdr machine list`만 건너뛴다
