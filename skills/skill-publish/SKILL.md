# Skill Publish

스킬을 **어디에 둘지 결정 → 뼈대 생성 → 내용 작성 → 전역 배선 → 비밀값 스캔 → 커밋** 순서로 처리한다.

```bash
<이 스킬 디렉토리>/skill.sh new <이름>      # 뼈대 생성
<이 스킬 디렉토리>/skill.sh link            # 세 런타임 전역 경로에 심볼릭 링크
<이 스킬 디렉토리>/skill.sh scan [이름]     # 비밀값·개인정보 스캔
<이 스킬 디렉토리>/skill.sh publish <이름>  # 스캔 통과 시 그 스킬만 스테이징
<이 스킬 디렉토리>/skill.sh status          # 스킬 목록 + 런타임별 링크 수
```

## 1. 어디에 둘지 먼저 정한다 ★

이 결정을 건너뛰면 사내 정보가 공개 저장소로 나간다.

| 성격 | 위치 | 전역 사용 |
|---|---|---|
| 범용 도구·개인 워크플로 | 공유 config 저장소의 `skills/` | `install.sh`가 세 런타임에 링크 → 어디서든 |
| 업무 도메인 지식이 본질인 것 (사내 시스템·프로세스·조직 고유 규칙) | **업무 저장소의 `.agents/skills/`** | 그 저장소 작업에서만 |

**공유 config 저장소가 공개(public)인지 반드시 먼저 확인한다** (`gh repo view <owner>/<repo> --json visibility`).
공개라면, 범용 스킬이라도 본문의 예시에서 회사명·사내 프로젝트명·동료 이름·내부 도메인을 일반화한 뒤에 올린다.
예시를 지우라는 게 아니라 **일반화**하라는 것이다 — "제목이 프로젝트 이름인데 본문은 메시지 초안" 같은 식으로 구조만 남긴다.

## 2. SKILL.md 작성

- **`description`에 사용자가 실제로 칠 법한 트리거 문구를 사용자의 언어로 넣는다.** 이게 자동 발동을 결정한다. 기능 설명만 있으면 사용자가 이름을 정확히 부르기 전엔 안 뜬다
- **실제로 밟은 함정을 적는다.** happy path만 적힌 문서는 다음 실행에서 같은 데를 또 밟게 한다. 시행착오가 곧 이 문서의 가치다
- **전제조건을 명시한다** — OS 의존(예: macOS 전용 osascript), 필요한 권한, 의존하는 MCP 서버
- 헬퍼 스크립트 경로는 "이 스킬 디렉토리" 기준으로 쓴다. **절대경로를 박으면 사본·링크가 여러 곳이라 깨진다**
- 스크립트는 `chmod +x` 를 잊지 않는다

## 3. 전역 배선

`install.sh`가 저장소의 각 스킬을 세 곳에 심볼릭 링크한다.

```
~/.claude/skills/<name>            Claude Code
~/.codex/skills/<name>             Codex
~/.config/opencode/skills/<name>   OpenCode
```

- `~/.claude/skills`는 **프로젝트와 무관하게 모든 세션에서 로드되는 사용자 레벨 경로**다. 여기 링크가 걸리면 추가 작업 없이 전역이다
- 프로젝트 레벨(`<repo>/.claude/skills`)은 다르다 — 상위 탐색이 git 루트에서 멈추므로 저장소 안에 링크를 따로 놔야 한다
- **`install.sh`는 대상 경로에 심볼릭 링크가 아닌 실제 디렉토리가 있으면 건너뛴다.** 먼저 실본을 저장소로 옮기고(`mv`) 링크로 대체한다
- 스킬이 의존하는 MCP 서버는 **user 스코프**(`~/.claude.json` 최상위 `mcpServers`)에 있어야 어디서든 붙는다. 프로젝트 스코프면 그 프로젝트에서만 동작한다

## 4. 스캔 — 공개 커밋 전 필수

`skill.sh scan`이 세 갈래로 본다.

1. **일반 비밀 패턴** — Slack/OpenAI/AWS/GitHub 토큰, 개인키, Bearer, 이메일 주소, `/Users/<이름>/` 절대경로, tailnet·내부 도메인
2. **대입식 비밀값** — `token = ...` 형태. `${ENV}` 참조는 비밀이 아니므로 제외한다
3. **조직 고유 패턴** — 회사명·내부 도메인·프로젝트명·동료 이름

3번은 **저장소 밖 로컬 파일**(`~/.config/skill-publish/patterns.local`, 한 줄에 하나)에 둔다.
스캐너 자체에 회사명을 박으면 **그 스캐너가 공개되는 순간 그게 곧 노출**이다. 파일이 없으면 스캔이 그 항목을 건너뛰었다고 경고하니, 경고가 뜨면 사람에게 알린다.

## 5. 커밋

**해당 스킬 디렉토리만 스테이징한다.** 설정 저장소에는 대개 관계없는 미커밋 변경이 남아 있고, `git add -A`로 그걸 같이 올리면 의도치 않은 게 공개된다.
실제로 dotfile 쪽 미커밋 변경에 사내 credential 호스트와 사내 경로가 들어 있던 적이 있다 — 커밋 이력은 깨끗한데 작업 트리만 오염된 상태였다.
`git status`에 남은 다른 변경이 있으면 **커밋하지 말고 사용자에게 알린다.**

## 6. 검증

- 링크 경유로 헬퍼를 실행해 본다 (`~/.claude/skills/<name>/...`)
- `skill.sh status`로 세 런타임 링크 수를 확인한다
- 스킬 목록에 뜨는지 확인한다. 새로 만든 스킬은 **세션 재시작 후**에 보이는 경우가 있다

## 검사기는 음성 대조로 검증한다 ★

스캐너가 "깨끗함"을 반환했다고 바로 믿지 않는다. **가짜 토큰·이메일·회사명을 심은 파일을 만들어 실제로 잡히는지 확인한 뒤**에 그 결과를 신뢰한다.
실제로 스캐너가 조용히 전부 통과시킨 적이 있는데, 원인은 아래 zsh 함정이었고 겉보기에는 정상 통과와 구별되지 않았다.

```bash
SKILL_REPO=<임시디렉토리> skill.sh scan <가짜스킬>   # 종료코드 1과 함께 항목이 잡혀야 정상
```

## 알아둘 것 (zsh)

- **`path`는 zsh에서 `PATH`와 연동된 특수 변수다.** `path="..."`로 문자열을 넣는 순간 `PATH`가 망가져 이후 모든 외부 명령이 `command not found`가 된다. 그런데 `grep`이 실패해도 "매치 없음"과 출력이 비슷해서, **검사가 조용히 통과한 것처럼 보인다.** 변수명으로 `path`·`cdpath`·`fpath`·`manpath`를 쓰지 말 것
- `"$n개"`처럼 변수 뒤에 한글이 붙으면 **`n개`라는 변수명으로 읽는다** → `"${n}개"`로 감싼다
- `for i in $ids`는 단어 분할이 일어나지 않는다 → 배열(`"${arr[@]}"`)이나 `while read`를 쓴다
