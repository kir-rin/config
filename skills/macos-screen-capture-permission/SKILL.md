# macos-screen-capture-permission

macOS 화면 기록 권한 버그는 **"설정엔 켜져 있는데 실제로는 권한이 없는"** 상태에서 시작한다.
이 스킬은 그 상태를 증거로 확인하고(진단), 앱이 그 상태를 스스로 알아차려 사용자가 쉽게 복구하게 만들고(수정),
실제 맥에서 끝까지 밟아 본다(검증).

## 0. 도구

```bash
<이 스킬 디렉토리>/diagnose.sh "/Applications/<앱>.app"   # 서명·번들 ID·지정 요건 읽기 전용 진단
```

## 1. 진단 — 증상에서 원인까지

| 증상 | 뜻 |
|---|---|
| 캡처에 대상 창 대신 **배경화면(+메뉴바·자기 창)만** 나옴 | 그 프로세스에 화면 기록 권한이 **실제로** 없다. `CGWindowListCreateImage`·`CGDisplayCreateImage` 계열은 권한이 없으면 실패하지 않고 다른 앱 창을 뺀 이미지를 준다 |
| 권한을 켰는데 시스템 요청 창이 **또** 뜸 | 설정 목록의 항목이 **지금 실행 중인 바이너리와 다른 빌드**를 가리킨다 |
| **업데이트할 때마다** 다시 막힘 | 서명이 ad-hoc 이거나 없다 → 빌드마다 코드 해시가 바뀌어 TCC 허용이 따라오지 않는다 |

확인 순서:
1. `diagnose.sh` 로 서명을 본다. `Signature=adhoc`, `TeamIdentifier=not set`, 코드 ID가 `<이름>-<해시>` 꼴이면 원인 확정. 두 버전의 코드 ID가 서로 다르면(빌드마다 해시가 바뀜) 더 확실하다.
2. 설치 시각(앱 번들 mtime)과 사용자가 권한을 켠 시점을 비교한다 — 그 뒤에 업데이트됐으면 그 허용은 예전 빌드 몫이다.
3. 앱 로그에 권한 판정이 찍히게 해 두었다면(아래 3번) 그 줄을 본다.

## 2. 즉시 복구(사용자 안내용)

```bash
tccutil reset ScreenCapture <번들 ID>   # sudo 불필요(그 사용자 범위). 존재하지 않는 ID면 -10814 오류
```
→ 앱 재실행 → 요청 창에서 [시스템 설정 열기] → 토글 켜기 → **앱 완전히 종료 후 다시 열기**.
설정 목록에서 항목을 `−` 로 지우고 다시 추가해도 같다.

## 3. 앱 수정 패턴 — 권한 없는 상태를 앱이 스스로 다룬다

| 단계 | 구현 |
|---|---|
| 캡처 전 확인 | `CGPreflightScreenCaptureAccess()` 가 false면 **찍지 않고** 안내를 띄운다(배경화면 이미지를 결과로 쓰지 않는다) |
| [권한 다시 켜기] | ① `/usr/bin/tccutil reset ScreenCapture <자기 번들 ID>` ② `CGRequestScreenCaptureAccess()` ③ `open "x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture"` |
| [다시 시작] | 허용 뒤 앱 재시작(Tauri `app.restart()` 등). 실행 중 프로세스는 예전 판정을 계속 본다 |
| 설정 화면 | "화면 기록: 허용됨 / 필요" 상태 + 같은 두 버튼. Windows 등 비대상 OS에선 숨김 |
| 업데이트 직후 | 앱 데이터 디렉터리에 "허용됐던 버전"을 기록하고, 새 버전 첫 실행에서 권한이 없으면 안내를 미리 띄움 |

구현 규칙:
- `tccutil` 은 **절대경로 + 고정 인자 + 셸 없이** 실행한다. 번들 ID는 설정 파일(예: `tauri.conf.json` identifier)과 같은지 테스트로 묶는다 — 다른 앱 권한을 지우면 안 된다.
- 권한 판정·표식 판정 같은 순수 로직은 분리해 단위 테스트한다. OS 호출은 `cfg(target_os = "macos")` 로 가둔다.
- "허용됐던 버전" 표식은 이 기능이 들어간 버전부터 쌓인다 — 기능 도입 직후 첫 업데이트에서는 미리 안내가 뜨지 않고, 캡처 시 안내로만 잡힌다.
- 근본 해결은 서명이다. Developer ID 서명(+공증)이면 지정 요건이 "번들 ID + 팀 ID"가 되어 업데이트해도 허용이 유지된다. 그 전까지는 위 흐름이 업데이트마다 필요하다.

## 4. 실기 검증 — 사람 손이 필요한 구간을 먼저 정한다

자동화로 되는 것과 안 되는 것을 나눈다.

| 단계 | 자동화 | 비고 |
|---|---|---|
| 새 버전 설치(릴리스 DMG를 받아 `/Applications` 에 교체) | 가능 | 교체 전 실행 중 프로세스 종료. `hdiutil attach -nobrowse -mountpoint …` → `ditto` |
| 실행 후 로그에서 "권한 없음" 판정 확인 | 가능 | 업데이트 직후라면 없음이 정상 |
| 캡처 단축키 누르기 | **보통 불가** | 터미널(osascript)에 손쉬운 사용 권한이 없으면 `키스트로크를 보내도록 허용되지 않습니다 (1002)` |
| 화면 스크린샷으로 안내창 확인 | **보통 불가** | 터미널에 화면 기록 권한이 없으면 `screencapture` 가 `could not create image from display` |
| 시스템 설정 토글 켜기 | 불가 | 사용자가 직접 |

그래서: 설치·로그 감시는 에이전트가 하고(`tail -F <앱 로그> | grep 권한`), 단축키·버튼·토글은 사용자에게
번호 매긴 단계로 맡긴 뒤 로그 줄로 각 단계를 확인한다. 검증 시나리오:
1. 업데이트 직후 실행 → 로그 "권한 없음", (표식이 있으면) 미리 안내창
2. 캡처 단축키 → 배경을 찍지 않고 안내창
3. [권한 다시 켜기] → 시스템 요청 창 + 설정 화면, 토글 켜기
4. [다시 시작] → 재실행 로그에 "권한 있음", 캡처에 대상 창이 제대로 찍힘
5. 설정 화면 상태 표시가 "허용됨"

## 알아둘 것

- **개발 빌드에서 [권한 다시 켜기]를 누르면 설치본 권한도 지워진다** — 같은 번들 ID를 쓰기 때문.
- 에이전트가 사용자 동의 없이 `tccutil reset` 을 사용자 앱 ID로 돌리지 않는다. 사용자의 현재 권한 상태를 바꾸는 일이다. sudo 없이 되는지 시험할 땐 관계없는 기본 앱 ID(예: `com.apple.Chess`)로 한다.
- macOS 15+ 는 `CGWindowListCreateImage` 류(레거시 캡처)를 쓰는 앱에 주기적으로 "계속 허용" 재확인 창을 띄운다. 이번 버그와 별개이며, 없애려면 ScreenCaptureKit(시스템 피커)로 옮겨야 한다.
- "권한 확인이 잘못 false를 주면 캡처가 전면 차단된다"는 리뷰 지적이 나올 수 있다 — 근거 없는 추측이면 코드 대신 실기 확인으로 답한다.
- **Windows 는 이 문제가 없다.** 데스크톱 앱 화면 캡처(GDI BitBlt·DXGI·Windows.Graphics.Capture)에 권한 체계가 없다. 예외: `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 창·DRM 영상은 검게, UAC 보안 데스크톱·잠금 화면은 안 찍힌다. 미서명은 SmartScreen 설치 경고만 낸다.
- 전제: macOS 10.15+(Preflight/Request API), `codesign`·`spctl`·`tccutil`(기본 탑재).
