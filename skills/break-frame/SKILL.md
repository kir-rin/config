# 틀 깨기

## 언제 사용하나
- "여전히 문제가 있다"
- "제자리걸음이다"

## 핵심 원칙
문제를 바꾸는 게 아니라 **문제를 보는 틀**을 바꾼다.

## 과정

### 1. 현재 틀 식별
- 무엇을 당연하다고 가정하나?
- 스스로 걸은 제약은?

### 2. 근본 질문
- 꼭 이렇게 풀어야 하나?
- 반대로 접근하면?
- 다른 분야에선 어떻게 풀까?

### 3. 관점 전환
- **사용자 관점**: 이게 진짜 문제인가?
- **시스템 관점**: 근원이 다른 곳에 있나?
- **비즈니스 관점**: 기술적 해결이 최선인가?

### 4. 대안 제시
- 반대 접근은?
- 문제 자체를 없앨 수 있나?
- 다른 누가 이미 풀었나?
