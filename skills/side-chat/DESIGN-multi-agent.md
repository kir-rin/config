# 설계 필요 — Claude Code 외 에이전트 지원

> 상태: **미착수. 설계가 먼저 필요하다.**
> 이 문서는 "왜 지금 안 되는가"와 "무엇을 정해야 하는가"만 적는다. 구현안은 아직 없다.

## 지금 되는 범위

herdr 페인 안에서 도는 **Claude Code 세션**만 지원한다. 다음은 이미 전역이다.

- 스킬 위치 `~/.claude/skills/side-chat/` — 모든 프로젝트에서 로드됨
- 키바인딩 `~/.config/herdr/config.toml` — 사용자 단위라 모든 herdr 세션에 적용
- 소켓 라우팅 — herdr가 페인마다 `HERDR_SOCKET_PATH`를 주입하므로 다중 herdr 세션도 자동으로 맞는 소켓을 찾아간다
- 상태 파일 — 세션 슬러그 + pane id로 키를 잡아 세션 간 충돌이 없다

## 왜 다른 에이전트로 확장이 안 되는가

곁가지 대화의 핵심은 **"현재 대화의 전체 맥락을 그대로 물려받은 새 세션"** 이고,
지금은 그걸 Claude Code의 두 기능에 전적으로 기대고 있다.

```bash
claude --resume <session-id> --fork-session
```

- `--resume <id>` — 기존 세션 전사(transcript)를 이어받는다
- `--fork-session` — 이어받되 **원본에 쓰지 않고** 새 세션 ID로 갈라진다

`--fork-session`이 없으면 곁가지에서 한 대화가 원본 세션에 섞인다. 이 스킬의 전제가 무너진다.

추가로 세션 ID를 얻는 경로도 Claude 전용이다.

- `herdr pane get`의 `agent_session.value` — herdr가 Claude 세션 ID를 인식해 붙여주는 값
- 전사 파일 존재 확인 `~/.claude/projects/<cwd를 -로 치환>/<session-id>.jsonl`

## 정해야 할 것

### 1. 대상 에이전트별 "포크"의 대응물이 있는가

| 에이전트 | 확인할 것 |
|---|---|
| Codex | 세션 재개 명령이 있는가. 있다면 원본을 건드리지 않고 갈라지는 옵션이 있는가 |
| OpenCode | 위와 동일 |

**없다면 대안 두 가지 중 하나를 골라야 한다.**

- **(a) 전사 복사 방식** — 원본 전사를 읽어 새 세션의 초기 입력으로 넣는다.
  맥락은 옮겨지지만 "이어받기"가 아니라 "요약·재주입"이 되어 충실도가 떨어진다.
  토큰 비용도 매번 든다.
- **(b) 그 에이전트는 지원하지 않는다** — 키를 눌러도 "Claude 세션에서만 됩니다" 토스트를 띄운다.
  정직하지만 기능이 반쪽이 된다.

### 2. 세션 ID를 어떻게 얻는가

herdr가 Codex·OpenCode 페인에도 `agent_session.value`를 채워주는지 확인이 필요하다.
안 채워준다면 에이전트별로 별도 조회 경로를 만들어야 하고, 그 순간 이 스킬은
"herdr + Claude"에서 "herdr + N개 에이전트"로 복잡도가 뛴다.

### 3. 전사 파일 경로 규칙

`session_file_exists()`가 Claude의 `~/.claude/projects/...` 구조를 하드코딩하고 있다.
에이전트마다 다르면 경로 해석을 추상화해야 한다.

### 4. 그래서 확장할 가치가 있는가 — 먼저 답할 질문

- 실제로 Codex·OpenCode 페인에서 곁가지 대화를 쓰고 싶은 상황이 있었나?
- (a) 전사 복사 방식의 낮은 충실도를 감수할 만한가?
- 아니면 **Claude 전용으로 못 박고 문서에 명시하는 편이 나은가?**

마지막 선택지가 현재로서는 가장 비용 대비 합리적으로 보인다.
확장을 결정하기 전에 위 1~3의 사실 확인이 선행되어야 한다.

## 지금 하지 않기로 한 이유

- `--fork-session`에 대응하는 기능이 다른 에이전트에 있는지 **확인되지 않았다**
- 확인 없이 (a) 전사 복사 방식으로 만들면, 원본과 다른 품질의 곁가지가 생겨
  "맥락을 물려받는다"는 이 스킬의 약속이 에이전트마다 달라진다
- 현재 실사용은 Claude Code 페인에 몰려 있어 급하지 않다
