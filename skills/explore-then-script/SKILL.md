# 탐색 → 판단 → 대본

AI 가 화면을 한 걸음씩 누르면 걸음마다 5~10초(화면 읽기·판단)가 든다. 그래서 **탐색은 한 번만** 하고, 밟은 흐름은 **고정 대본**으로 굳혀 그 뒤로는 대본만 돌린다. AI 는 대본이 실패한 장면만 본다.

## 전제
- `agent-browser` (세션·녹화·snapshot·cdp-url). 로그인이 필요한 사이트면 저장된 로그인 상태로 세션을 연다(사람만 비밀번호 입력).
- 탐색·대본 모두 **사용자가 띄워 둔 같은 창(세션)** 에서 할 수 있다. 사용자가 그 창을 보고 있을 수 있으니 세션을 닫거나 새 창을 열지 않는다.
- Node 18+ (아래 `cdp-watch.mjs`, 내장 WebSocket).

## 0. 시작 전에 정한다 (사용자에게 한 번 묻기)
- **눌러도 되는 것 / 안 되는 것.** 기본값: 읽기·이동·거르기·편집 열기(저장 안 함)·테마·폭 바꾸기는 됨. **보내기·저장·생성·삭제·결재는 안 됨** — 「안 해 본 것」 목록으로만 남긴다. 보내기는 「나에게 시험 보내기」처럼 본인에게만 가는 것만.
- 그 레포의 디자인 규칙 문서(있으면 경로)와 대상 사용자(예: 비개발 담당자).
- 시간 상자(예: 20분).

## 1. 탐색
1. **캐시 무시 새로 고침부터.** 창에 옛 판이 남아 있으면 이미 고친 문제를 다시 적는다(실제로 겪음).
2. 화면은 **snapshot(접근성 트리 글)** 로 보고, 모양이 의심될 때만 스크린샷을 읽는다. 장면마다 그림을 읽으면 몇 배 느려진다.
3. 감시를 같이 건다: `node <이 스킬 디렉토리>/cdp-watch.mjs "$(agent-browser --session <세션> get cdp-url)"` — 네트워크 4xx/5xx(본문 앞부분)·콘솔 에러·예외를 한 줄씩. 처음 한 번 뜨는 허락 요청(409 등)·로그인 탐침 같은 소음은 grep -v 로 거른다.
   - **화면에만 뜨는 판단 에러는 네트워크·콘솔에 흔적이 없다.** 페이지가 에러 글을 띄울 때 `console.error("[app] " + 글)` 한 줄을 남기게 하면 감시가 잡는다(권장, 대상 앱 코드 몫).
4. 폭 390·1440, 라이트·다크를 한 번씩.
5. 결과는 표 하나: `# · 어디 · 한 것 · 일어난 것(화면 글 그대로, 로그 id) · 기대 · 심각도(막힘/불편/모양) · 기준 · 캡처`. 사람 값(이름·사번 등)은 줄 번호로 바꾼다.

### UI/UX 기준 (표의 「기준」 칸 이름표)
| 기준 | 보는 것 |
|---|---|
| 끝까지 | 그 화면으로 사람이 하려는 일을 끝낼 수 있나, 중간에 막히나 |
| 상태 | 무엇이 골라졌고·거르는 중이고·저장 전인지 보이나, 말없이 사라지는 입력은 없나 |
| 빈·에러 | 0건·실패·아직 안 고름일 때 이유와 다음 행동(버튼)이 있나 |
| 사람 말 | 개발 용어·코드·ms·원래 값(TRUE/FALSE, 일련번호 날짜)이 그대로 보이나 |
| 보이는 대로 | 화면에 보이는 모양(날짜·쉼표 숫자)으로 찾고 고를 수 있나 |
| 되돌리기 | 실수를 되돌리는 길이 있나, 되돌릴 수 없는 일 전에 묻나 |
| 일관 | 같은 일은 같은 말·모양인가, 이름이 겹치거나 반복되나 |
| 반응 | 누르면 바로 반응하나, 3초를 넘으면 진행이 보이나 |
| 폭·테마 | 좁은/넓은 폭, 라이트/다크에서 잘림·겹침·흰 기본 스크롤바 |
| 접근성 | 키보드로 닿나, 눌린 상태(aria-pressed)가 읽히나, 글자 대비 |

끝에 기준별 한 줄 요약(통과 / 걸림 n건)과 **「안 해 본 것 — 이유」** 목록.

## 2. 판단 (사용자에게 먼저 보인다)
표의 줄마다 **반영 / 보류 / 버림**. 사용자가 말하지 않은 기능을 새로 만드는 지적(예: 정렬·개수 연동)은 보류로. 확인 안 된 원인은 「확인 안 됨」. 반영할 것만 고치는 쪽(같은 작업자에게 이어서)으로 보낸다.

## 3. 굳히기 — 대본
실제로 밟은 흐름을 `<레포>/test/flows/<화면>.flow.sh` 로 적는다(뼈대: `<이 스킬 디렉토리>/flow-template.sh`).
- 걸음 = `step "이름" <agent-browser 명령…>` + `expect_text "보여야 할 글"` / `expect_no_text "개발 용어"`.
- 대본엔 **기계로 확인되는 것만**: 빈 상태 글 있음, 금지어 목록(개발 용어·ms·TRUE/FALSE) 없음, 에러 줄 없음, 걸음당 시간 상한. 「헷갈림」 같은 판단은 탐색 몫.
- 보내기는 본인에게 가는 것까지만 넣는다.
- 실패한 걸음만 스크린샷을 남기고 끝에 요약 한 줄(통과 n / 실패 n). AI 는 실패 캡처만 본다.

## 4. 다시 돌리기
화면을 고친 뒤 **올리기 전에 대본만** 돌린다. 새 기능을 더했으면 그 흐름을 대본에 한 걸음 더한다. 대본이 3번 연속 같은 곳에서 깨지면 화면 구조가 바뀐 것 — 탐색을 한 번 다시.

## 밟은 함정
- 창에 옛 판 캐시 → 고친 걸 다시 버그로 적음. 시작할 때 새로 고침.
- 장면마다 스크린샷을 읽으면 한 걸음 10초. snapshot 글 먼저.
- 「요청 성공 + 페이지 판단 실패」는 네트워크·콘솔 감시에 안 잡힘 → 페이지에 console.error 한 줄.
- 감시 스크립트가 빈 줄을 에러로 셈 → 빈 줄 거르기.
- 감시는 30분 등 시한이 있으면 다시 걸어야 하고, 사용자가 창을 닫으면 끊긴다(「연결이 끊겼어요」 한 줄로 알림).
- 로그인 저장은 창을 **닫을 때** 일어난다. 로그인을 마치기 전에 닫힌 창은 저장본에 로그인이 없다.
- 「저장」「+ 만들기」 같은 단추는 누르면 실제로 생긴다 — 대본에도 넣지 않는다.
