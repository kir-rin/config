# Apple Notes Tidy

애플 메모를 **인벤토리 → 요약 → Slack 대조 → 병합/분리 판단 → 사용자 선택 → 실행 → 검증** 순서로 정리한다.
핵심은 요약과 Slack 대조다. 제목이 `테스트`·`Tmp`·`메모`처럼 무의미한 경우가 많아 제목만으로는 아무 판단도 못 한다.

## 0. 도구

```bash
<이 스킬 디렉토리>/notes.sh          # 서브커맨드 목록
notes.sh folders                     # 폴더별 메모 수
notes.sh recent 14 400               # 최근 14일, 본문 400자까지 (폴더·제목·날짜·첨부·id·본문)
notes.sh body <id>                   # 전문
notes.sh delete <id>...              # 휴지통으로
notes.sh move <폴더명> <id>...        # 폴더 이동
notes.sh merge <대상id> <원본id> [문구]  # 본문 이어붙이기
notes.sh trash / restore <id>...     # 휴지통 확인 / 되살리기
```

출력이 크면 스크래치패드로 리다이렉트한 뒤 나눠 읽는다. `NoteStore.sqlite` 직접 조회는 **TCC(전체 디스크 접근)로 막혀 있으니 시도하지 말 것** — AppleScript가 유일한 경로다.

## 1. 인벤토리와 기존 분류 체계 파악

`folders`로 폴더와 개수를 보고, **기존 폴더 각각에 이미 들어있는 메모를 읽어 그 폴더의 기준을 역추출한다.** 사용자가 전에 만든 카테고리가 있으면 새 체계를 만들지 말고 그 기준을 따른다.
그다음 `recent`로 대상 기간의 메모를 덤프한다.

## 2. 표로 요약

폴더별로 묶어 마크다운 표를 만든다. 컬럼: `제목 · 요약 · 제안`.
요약은 제목 복붙이 아니라 **뭘 하다 어디서 멈췄는지**를 쓴다. 그리고 다음을 반드시 표시한다:

- **한 노트에 두 주제가 섞인 것** — 아주 흔하다. 옮기기 전에 분리가 필요하다
- **제목과 내용이 다른 것** — 제목은 프로젝트 이름인데 본문은 남에게 보낼 메시지 초안인 식
- **1~3줄짜리 단편** — 병합 대상

## 3. Slack 대조 — 이미 나간 것 골라내기 ★

메모의 상당수가 **슬랙에 보내기 전 초안**이다. 이미 보냈으면 메모는 역할이 끝났으므로 삭제 후보다.
본문에 인사말·존댓말 문장(`안녕하세요`, `~님`, `부탁드립니다`)이나 공지문 틀이 보이면 초안으로 의심하고 반드시 대조한다.

```
slack_search_messages: from:@<본인핸들> <초안에서 뽑은 특징적인 문구 6~10자>
```

- **검색 히트 → 발송 완료 → 삭제 후보.** 초안과 발송본이 다르면 발송본이 최종본이므로 메모를 버려도 정보 손실이 없다
- **채널 공지·회의록 공유로 반영된 것도 동일** — 노트의 담당자 배정·결정사항이 공지에 그대로 올라갔는지 본다
- **스크럼 채널의 "어제 한 일"**도 완료 증거로 쓴다 (`[가이드] ○○님께 전달` 같은 줄)
- **검색 0건 → 미발송 → 유지.** 아직 보내야 할 것일 수 있으니 오히려 눈에 띄게 표시한다

검색어는 고유명사보다 **문장 중간의 특이한 구절**이 잘 맞는다 — 초안에서 6~10자 정도의 흔치 않은 단어 조합을 그대로 떼어내 쓴다. 사람 이름만으로는 노이즈가 많다.

## 4. 병합·분리 판단

- **같은 날 같은 작업의 조각들** — 가장 큰 병합 이득. 경로·비교표·설정스펙이 따로 흩어져 있으면 하나만 봐선 못 쓴다
- **회고·아이디어 단편** — 1~3줄짜리를 날짜 구분선과 함께 한 노트에 모은다
- **제목이 같거나 띄어쓰기만 다른 것**(`하고싶은 것` / `하고 싶은 것`) — 무조건 병합 후보
- 병합은 **원본을 지우고 새로 쓰는 작업이라 되돌리기가 번거롭다.** 묶음 단위로 제시하고 사용자가 고르게 한다

## 5. 사용자 확인 (건너뛰지 말 것)

추천만 하고 고르게 한다. 알릴 것:

- 노트 삭제는 **휴지통(Recently Deleted)으로 가서 30일간 복구 가능**하다 — 먼저 말해주면 결정이 빨라진다
- 크레덴셜이 평문으로 든 노트(`비번`, `~ 접속 정보`, 토큰이 든 것)는 **본문을 열지 않는다.** 존재만 보고하고, 메모 잠금이나 Keychain 이전을 권한다
- 지시가 갈리면 실행 전에 되묻는다 (폴더 라벨 vs 노트 제목, "A 빼고 다 빼줘"의 A가 추천 대상일 때)

## 6. 실행

**모든 조작은 note id로 한다.** AppleScript의 인덱스 참조(`note 3 of folder …`)는 본문 수정이나 삭제 직후 정렬이 바뀌며 **다른 노트를 가리키게 된다.** 실제로 `set body of tgt` 직후 같은 참조를 읽었더니 전혀 다른 노트가 나왔다. 조회 단계에서 id를 확보하고, 이후 delete/move/merge는 전부 id로 건다.

삭제 전에는 **드라이런**으로 대상 목록을 뽑아 사용자에게 보여주고 개수를 맞춘다(`매칭 19 / 목표 19`).

### 폴더 삭제는 다르다 ⚠️

- 폴더를 지우면 **안의 메모가 휴지통으로 가지 않는다.** 휴지통 개수가 늘지 않는 걸로 확인된다
- 게다가 **iCloud가 잠시 뒤 폴더를 통째로 되살리는 경우가 있다** — 로컬 삭제가 그대로 남지 않는다
- 그래서 순서는 항상 **① 안의 메모를 `delete`로 휴지통에 보내고 → ② 빈 폴더를 삭제**한다. 이러면 메모는 복구 가능하고 폴더 삭제도 남는다
- 워크스페이스의 마지막 노트를 옮기면 폴더가 저절로 사라진다

### 병합

`merge`는 `body`(HTML)를 이어붙인다. 이러면 **첨부(이미지)까지 넘어온다** — 실행 전후 첨부 개수를 비교해 확인한다. 원본은 자동으로 지우지 않으니, 결과를 확인한 뒤 별도로 `delete` 한다.

### zsh 주의

이 환경의 셸은 zsh다. `for i in $ids`는 **단어 분할이 일어나지 않아** 전체가 한 덩어리로 넘어간다. 반드시 배열(`ids=(a b c)` + `"${ids[@]}"`)이나 `while read`를 쓴다.

## 7. 검증 후 보고

`folders`를 다시 돌려 개수 변화를 확인하고, **닫은 것 / 남은 것 / 안 한 것**을 나눠 보고한다.
특히 **분류 이동을 실제로 했는지 안 했는지**를 분명히 말한다 — 초안만 만들고 실행 안 한 상태를 완료로 오해하기 쉽다.

## 알아둘 것

- 메모 수정일은 iCloud 동기화로 갱신될 수 있지만, AppleScript의 `modification date`는 대체로 실제 편집 시각과 맞는다
- 초 단위까지 포함한 `modification date as string`은 사실상 유일 키라 제목이 겹칠 때(`테스트` 7개) 식별자로 쓸 수 있다. 다만 이후 조작은 id로 한다
- 미분류 기본 폴더(`Notes`)에 수백~수천 개가 쌓여 있는 게 보통이다. 한 번에 다 하려 하지 말고 기간을 끊어서 반복한다
