# 구현 agent 공통 규칙 (틀 — 프로젝트마다 복사해 레포·신원·데이터 규칙을 채운다)

- 레포: <레포 경로>(브랜치 <브랜치>). push 금지. 커밋 전 `git var GIT_AUTHOR_IDENT` 가 <신원> 인지 확인, 다르면 커밋하지 말고 보고.
- 요구사항 근거: 받은 과업 설명(brief) + 계획의 Global Constraints·Rulings·Interfaces·사용자 결정 절 + 결정 기록 파일. 결정 기록에 있는 결정은 다시 묻지 않는다. 계획 전체는 읽지 않는다.
- TDD: 실패하는 테스트 → 실패 확인(명령·출력) → 구현 → 통과 → 커밋 직전에만 전체 테스트 한 번. 과업 중에는 관련 테스트만.
- RED: 테스트를 먼저 쓰고 구현 전에 돌린 실패. 새 모듈이라 「기능 없음」으로 실패해도 된다(검토에서는 minor) — 다만 테스트가 원하는 동작을 실제로 단언해야 한다.
- 가짜 데이터만. 실데이터·시크릿·실명 금지, 실제 외부 호출(메일·메신저·외부 사이트) 금지. 비밀값은 로그·오류·응답에 넣지 않는다.
- 서브에이전트를 부르지 마라(구현 보조·리뷰 모두). 리뷰는 컨트롤러가 따로 한다.
- 막히면 BLOCKED / NEEDS_CONTEXT 로 구체적으로 멈춘다. 추측으로 채우지 않는다.
- 구현 전에 반복 지적 체크리스트(recurring-findings.md)를 읽고 해당 항목을 스스로 확인한다.
- 자기 diff 검토(완전성·이름·YAGNI·테스트가 실제 동작을 확인하는지) 뒤 보고.
- 보고 파일: 구현한 것, 테스트·결과, RED/GREEN 증거, 바뀐 파일, 자기 검토, 걱정. 컨트롤러에게는 짧게: Status, 커밋, 테스트 한 줄, 걱정.
- 검토 지적으로 다시 불리면: 고치고, 덮는 테스트를 돌리고, 보고 파일 끝에 fix round 절을 덧붙이고, 커밋하고, 같은 짧은 형식으로 답한다.
- 작업 폴더(장부·보고서)는 레포 밖에 둔다. 레포에 커밋하지 않는다.
