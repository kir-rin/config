# 전역 지침 — 목차

늘 지킬 것만 여기 둔다. 나머지는 아래 표의 상황이 오면 그 파일을 먼저 읽는다(2026-10-28 사용자 결정: 짧게, 인덱싱).

## 늘 지킨다
@~/.claude/identity.local.md

- 코드를 쓰거나 고치기 전 보안 기준: `~/KRAFTON_SECURITY.md`.
- **커밋 작성자는 회사 계정만**(실제 값은 아래 `identity.local.md`). 커밋 전에 `git var GIT_AUTHOR_IDENT` 로 확인하고,
  다르면 커밋하지 말고 알린다(`--author` 로 우회 금지). 개인 gmail·옛 계정 금지. 예외 레포 → `~/config/claude/global/git-identity.md`.
- **답은 짧게.** 결론 먼저, 산문 6줄·불릿 5개 이내, 코드 고친 뒤 설명 3줄 이내, 서론·요청 재진술·마지막 요약 문단 없음.
  비교는 표로, 파일은 `path:line`. 사용자가 「자세히」라고 할 때만 넘긴다. 상세 → `~/config/claude/global/answer-format.md`.
- **ADR·지난 결정은 그때의 판단이다.** 새 요청이 어긋나면 그쪽으로 끌지 말고 「ADR n 전제 X 와 어긋남」 한 줄 알린 뒤 새 요청 기준으로 설계, ADR 에 대체됨을 단다(2026-10-31). 대체할 때는 ① 새 방침을 거는 시험부터 쓰고(옛 동작이 남아 있으면 실패하게) ② 옛 전제를 쓰는 코드를 grep 해 「고침 / 남김 — 이유」를 ADR·STATUS 에 같이 적는다(2026-11-08, run_code 첫 판 API 를 부르지 않던 잔재).
- **상태·알림·예외를 늘리기 전에 「덜기 후보」 표로 묻는다**(남길 것은 안전선뿐 — `~/config/claude/subagent-plans.md` 22번, 2026-11-01).
- **필수만 넣고 편의는 기록만 하고 뺀다** — 빼도 사용자가 말한 일을 끝까지 할 수 있고 안전선도 안 깨지면 편의(같은 파일 24번, 2026-11-01).
- **기한 있는 일은 모두 `working-backwards` 로 한다** — 시작할 때 「기한 날 참이어야 할 한 문장」과 필수(5개 이하)부터 정하고, 계획·구현·제안·새 아이디어 전부 그 문장에 대 본다. 없어도 문장이 참이면 보류 표에 한 줄, 구현 안 함(사용자든 AI 든 같다, 2026-11-08).
- **재활용이 첫 추천이다.** 새 화면·버튼·능력을 제안하기 전에 레포에 같은 역할의 조각이 있는지 먼저 찾아, 그 조각이 그 일을 끝까지 해내면 첫 추천으로 두고 새로 만드는 안에는 왜 안 맞는지 한 줄 단다. 못 해내면 재활용 안은 「○○ 는 △△ 가 안 돼 제외」 한 줄만. 화면 규칙과 부딪혀도 재활용이 먼저(2026-11-04, 11-08 조건 추가).
- **사람이 직접 하는 게 빠르면 사람에게 권한다.** 앱 화면을 SSH·접근성 도구로 조작하거나, 모델 답·캡처를 기다려 눈으로 보는 확인처럼 사람이 붙여 넣고 눌러 보면 1~2분에 끝나는 일은, AI·subagent 로 돌리기 전에 붙여 넣을 글과 볼 것을 주고 직접 하도록 추천한다. 사용자가 맡기면 그때 AI 가 한다(2026-11-08).
- **안전선 아닌 대비책은 실제 운영 기록에 신호가 남은 뒤에 만든다** — 그 전엔 「보류 + 되살릴 신호」(같은 파일 23번, 2026-11-01).
- **subagent 는 `worker` 타입으로 띄운다**(MCP·스킬 없이 파일·셸·웹 도구만 — 시작 맥락 약 48K → 14K).
  Workflow 스크립트에서는 `agent(..., { agentType: 'worker' })`. 캔버스·아티팩트 일은 `artifact-worker`(Artifact 만 더함), 사내 시스템(One MCP)·봇 준비 일은 `company-worker`(One MCP 메타툴만 더함). 그 밖의 MCP·스킬이 꼭 필요한 일만 다른 타입으로.
- **subagent·워크플로우 결과는 보고만 보고 받지 않는다.** 받기 전에 실제 결과물(diff·파일·명령 출력) 하나는 직접 본다 — 보고는 검증 안 된 주장(pstack prove-it-works, 2026-10-31).
  분석·조사 보고의 원인·숫자·「있다/없다」를 결정에 쓰기 전, 일을 시작하기 전, 같은 전제의 고침이 두 번 실패했을 때는 `premise-check` 스킬을 따른다 — 전제를 적고 「틀렸다면 무엇이 보여야 하나」를 본다. 시각·건수·mtime 맞춰 보기는 확인이 아니고, 확인 못 한 주장엔 「확인 안 됨」(2026-11-02).
- 워크플로우·subagent 결과를 받으면 `agent-cost.py --chart --run <id>` 그림을 짧게 함께 보여 준다(`agent-cost` 스킬).
- **메인 세션은 늘 대화를 받는다(2026-11-09).** 메인은 대화·결정·subagent 결과 확인·몇 초짜리 조회만 하고, 코드 고치기·전체 시험·빌드·e2e·여러 파일 조사·끝나는 시간을 모르는 일은 전부 **백그라운드** subagent(`delegate_task`)에 맡긴다. 기다리는 subagent 도 메인을 막으므로 쓰지 않는다. 메인에서 전체 시험·e2e·빌드를 돌리면 hook(`main-long-guard.py`)이 막는다. 맡길 일이 생기면 바로 맡긴다. 기다리는 건 고칠 파일이 실제로 겹칠 때뿐이고, 겹치지 않으면 동시에 돌린다. 같은 폴더의 전체 시험만 겹치지 않게 맡긴 쪽에서 맞춘다.
- **오래 걸리는 일(1분 넘는 시험·빌드·대기)은 메인에서 하지 않는다** — `worker` subagent 하나에 끝 조건과 함께 맡기고, 메인은 **예상×1.5 에 한 번만** 깨어나 산출물(커밋·파일)로 살았는지 본다. 고정 주기 확인·메시지로 깨우기 없음. 사용자에겐 되돌릴 수 없는 일·진짜 결정만 묻는다(2026-11-08, 시험 재시도를 메인이 5번 돌린 뒤). 상세·pstack 근거 → `~/config/claude/global/long-tasks.md`.
