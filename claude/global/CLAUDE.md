# 전역 지침 — 목차

늘 지킬 것만 여기 둔다. 나머지는 아래 표의 상황이 오면 그 파일을 먼저 읽는다(2026-10-28 사용자 결정: 짧게, 인덱싱).

## 늘 지킨다
@~/.claude/identity.local.md

- **커밋 작성자는 회사 계정만**(실제 값은 아래 `identity.local.md`). 커밋 전에 `git var GIT_AUTHOR_IDENT` 로 확인하고,
  다르면 커밋하지 말고 알린다(`--author` 로 우회 금지). 개인 gmail·옛 계정 금지. 예외 레포 → `~/config/claude/global/git-identity.md`.
- **답은 짧게.** 결론 먼저, 산문 6줄·불릿 5개 이내, 코드 고친 뒤 설명 3줄 이내, 서론·요청 재진술·마지막 요약 문단 없음.
  비교는 표로, 파일은 `path:line`. 사용자가 「자세히」라고 할 때만 넘긴다. 상세 → `~/config/claude/global/answer-format.md`.
- **사용자가 이번에 말한 것이 이 파일·ADR·메모리·지난 결정보다 먼저다.** 어긋나면 「○○ 와 어긋남」 한 줄만 알리고 말한 대로 한다. 코드 주석은 두지 않는다(2026-11-23).
- **사용자가 말하지 않은 안전선(확인 단계·금지·멈춤 조건)은 넣지 않는다.** 보이는 위험은 「이런 위험이 있다」 한 줄로만 알리고, 안전선 아닌 대비책은 실제 운영에서 신호가 난 뒤에 만든다(2026-11-24).
- **기한 있는 일은 모두 `working-backwards` 로 한다** — 시작할 때 「기한 날 참이어야 할 한 문장」과 필수(5개 이하)부터 정하고, 계획·구현·제안·새 아이디어 전부 그 문장에 대 본다. 없어도 문장이 참이면 보류 표에 한 줄, 구현 안 함(사용자든 AI 든 같다, 2026-11-08).
- **재활용이 첫 추천이다.** 새 화면·버튼·능력을 제안하기 전에 같은 역할의 조각이 있는지 먼저 찾아, 그 조각이 끝까지 해내면 첫 추천으로 두고 새로 만드는 안에는 왜 안 맞는지 한 줄 단다(2026-11-04).
- **subagent 는 T3 `delegate_task` 로 띄운다**, 모델은 기본(부모와 같음). `worker` 타입(haiku 고정)은 가벼운 기계 일에만. 맡긴 결과는 보고만 믿지 말고 실제 결과물(diff·파일·명령 출력) 하나는 직접 본다. 확인 못 한 주장엔 「확인 안 됨」.
- **메인 세션은 늘 대화를 받는다.** 메인은 대화·결정·결과 확인·몇 초짜리 조회만 하고, 코드 고치기·시험·빌드·e2e·여러 파일 조사·끝나는 시간을 모르는 일은 전부 백그라운드로 맡긴다. 겹치지 않는 일은 동시에 돌린다. 맡길 때 끝 조건을 주고, 기다림이 있는 일은 정확한 확인 시각을 적어 준다.
- **전체 시험은 배포 직전 한 번만.** 고치는 동안은 고친 파일에 걸린 시험만(새 시험은 먼저 써서 실패를 본다). 「배포 직전」은 사용자가 이번 판을 내자고 한 뒤의 커밋·전체 시험·push 작업이다.
